# Utility commands

## Machine output

`--json` belongs to strictcli, not to rlsbl: it is recognized on every command that declares a payload, and no rlsbl command declares its own. In machine mode stdout carries one document, strictcli's machine-mode document, and the command's data is its `payload` member; human output is suppressed, and `--quiet` does not reach the document. `rlsbl help --json` publishes every command's payload schema. The framework's other flags are on every command too: `--dry-run` (on a mutating command, records the writes and programs as a would-do log instead of performing them), `--approve-consequential` (skips the confirmation a consequential command asks), `--quiet`, and `--verbose`.

## `rlsbl commit`

```bash
rlsbl commit --message "regenerate the docs" README.md .claude/CLAUDE.md
```

Commits the named files through safegit with the `Autogenerated: true` trailer, marking the commit machine-made so changelog coverage exempts it: the way to commit generated files (selfdoc output, a strictcli schema dump) by hand. Files are named relative to the working directory or absolutely and must lie in the repository; a named file that did not change is left out, a commit none of whose files changed is refused, and so is a file git ignores. safegit must be on `PATH`. A human-authored change is never committed this way: it needs a changelog entry.

## `rlsbl status`

```bash
rlsbl status
rlsbl status --target npm --registry
```

Reports on the member whose directory holds the working directory and one of its targets: the package name and version its manifest declares, the branch and whether the working tree is clean, the releasable's latest release (annotated when this checkout does not contain it, when its commit is unrecoverable, and with the versions archived above it that were never released), whether the changelog holds the released file of the current version, the changelog coverage of the commits since the nearest release this checkout contains, the member's own CI and publish workflows, and a warning when commits needing an entry are waiting. A member with several targets needs `--target`.

With `--registry`, the registry's package listing (npm's or PyPI's package document, or the Go module proxy's version list) gives the latest published version, compared with the local one: `AHEAD`, `BEHIND`, `SAME`, `UNPUBLISHED`, or `PUBLISHES_NOTHING` for a member whose releasable publishes nothing. No request names one version, and a registry that does not answer is an error. At a workspace root whose root member has no target, `status` refuses, naming `rlsbl monorepo status`.

## `rlsbl unreleased`

Lists the commits of the releasable the working directory selects since the nearest release this checkout contains, newest first, each marked `COVERED` (an unreleased entry names it), `EXEMPT` (it carries the `Autogenerated: true` trailer, or changes only rlsbl's records), or `MISSING`, with the coverage count. Only commits changing a file of the releasable's members or records are listed, and in a fork the upstream's history is left out. A member versioned under no releasable has no changelog and is refused.

| Output | What to do |
| --- | --- |
| Every commit covered or exempt | Ready to write the release file. |
| Some `MISSING` | `rlsbl changelog add --commits <ids> ...` for each. |
| No commits | Nothing to release. |

## `rlsbl targets`

Lists every target rlsbl supports with the files its version lives in, and whether the member whose directory holds the working directory has it: the targets it declares in `releasables.toml`, or, when it declares none, the ones its manifests are detected as ([release targets](targets.md)).

## `rlsbl discover`

```bash
rlsbl discover
rlsbl discover --mine
```

Lists the GitHub repositories carrying the `rlsbl` topic, most recently updated first, through the authenticated `gh`; `--mine` keeps the repositories the authenticated account owns. GitHub's search returns at most 1000 repositories, and a topic carried by more is refused rather than listed in part. Projects gain the topic from `rlsbl scaffold` while `rlsbl:ecosystem-tagging` is on.

## `rlsbl check-name` and `rlsbl claim-name`

```bash
rlsbl check-name widget gadget --target npm --target pypi --delay 1500
rlsbl claim-name widget --target npm --approve-consequential
```

`check-name` checks whether package names are usable. npm and PyPI are asked over the network, through the package-level pages that list a package's versions, whether the name and every name colliding with it after normalization are registered (PyPI's visually-similar rule included); go is an offline check of the Go package name a candidate implies (invalid when it is not a Go identifier or is a keyword, taken when a standard-library package has the name, discouraged for uppercase, underscores, or a predeclared identifier). Each name gets `available`, `taken`, `invalid`, `discouraged`, or `error`; a similar name the registry cannot answer about makes the verdict `error`, never `available`. `--delay` is the milliseconds between networked requests. It exits 0 when every name is available, 2 when a check ended in an error, and 1 otherwise.

`claim-name` publishes a minimal placeholder (version 0.0.0) under a name `check-name` reports available, and refuses any other verdict. npm authenticates with `NPM_TOKEN` when it is set, otherwise with `~/.npmrc`; PyPI with `UV_PUBLISH_TOKEN` or `PYPI_TOKEN`, otherwise with `~/.pypirc`. No token is ever printed or passed as an argument. A claimed name is held for good: neither registry gives it back. Checking or claiming a name contacts the registry with it, so only names the owner approved are checked.

## `rlsbl secrets sync-npm-token`

```bash
rlsbl secrets sync-npm-token --approve-consequential
rlsbl secrets sync-npm-token --all --approve-consequential
```

Copies the npm token in `~/.npmrc` into the `NPM_TOKEN` Actions secret of repositories that already have one. It refuses when `~/.npmrc` holds no token, and when npm does not accept it (asked with `GET https://registry.npmjs.org/-/whoami`); otherwise it prints the npm user the token authenticates. Without `--all` the target is the repository the working directory's `origin` names, and one without an `NPM_TOKEN` secret is refused: the secret is never created. With `--all` the targets are every repository the authenticated `gh` account can see that has the secret; archived ones are named and skipped. Every target is read before any is written, each is set with `gh secret set NPM_TOKEN --repo <owner/repo>` with the token on stdin, and the run exits 1 when any target could not be read or set. The `npm-token-synced` check names this command when a secret is older than the token.

## `rlsbl rewrite`

Each rewrite observes the tree, prints a per-file plan with occurrence counts under `--dry-run`, and refuses to write when a count moved between the preview and the write.

- **`rlsbl rewrite go-module-path --from-module <old> --to-module <new>`** renames one Go module path across the repository: the module-path tokens in every `go.mod` (the module directive and every `require`, `replace`, `exclude`, or `retract` naming it), every Go import under the old path (located with `go/parser`, rewritten in the import's string literal), and the `project_id` of every strictcli schema dump under it. A module nested under the old path with its own `go.mod` keeps its path; containment is boundary-aware, so a neighboring module whose path merely starts with the same letters is left alone. Only the files `git ls-files --cached --others --exclude-standard` lists are considered, minus `vendor/` and the scratch directories. A rename finding nothing to rewrite is refused, naming the module paths declared here.
- **`rlsbl rewrite uv-path-sources`** converts the member's path- and workspace-sourced Python dependencies into registry constraints floored at the version `uv.lock` resolves, keeping each entry's extras and environment marker, and deletes the matching `[tool.uv.sources]` entries. Each converted name joins the member's `internal_dep_floors`, and `rlsbl:dep-floors` is switched on for the member where it is off. A locked version PyPI's project document does not list is refused, naming the fix: release that dependency first.
- **`rlsbl rewrite project-name`** renames a standalone project's published identity ([renaming a standalone project](conversions.md#renaming-a-standalone-project)).
