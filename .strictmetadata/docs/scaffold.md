# Scaffold

`rlsbl scaffold` renders the release infrastructure of the member whose directory is the working directory, from rlsbl's templates and `.strictmetadata/releasables/releasables.toml`, and keeps it current. It writes no declaration of its own accord: a repository without `releasables.toml` is refused, showing the declarations of a standalone project. `--target <name>` adds a target the member neither declares nor has detected, and `--publish-mode ci|none` sets the member's releasable's publish mode, both edited into `releasables.toml` in place.

Everything is planned and every refusal made before anything is written. What the run wrote is committed with the `Autogenerated: true` trailer unless `--no-auto-commit` is passed. Running it again changes nothing that is current.

## What scaffold renders

| File | When |
| --- | --- |
| `.github/workflows/ci.yml` (or `ci-<target>.yml` beside another target's) | Each target the member has: the CI workflow, rendered for the npm package manager the lockfile names. A pypi workflow also builds the upload and checks it for [private paths](#private-paths). |
| `.github/workflows/publish.yml` | A releasable publishing from CI: the `wait-for-ci` job, then one job per pipeline publishing from CI ([pipelines](pipelines.md#publishing-from-ci)), rendered without build attestations, Go proxy requests, or repository URLs where the lifecycle-and-license record or GitHub's visibility forbids them. A releasable publishing nothing gets none, and a stale one is removed. |
| `VERSION` | A Go module, created at `0.0.0` when absent. A scaffold that would create it disagreeing with the version another target of the member declares is refused before anything is written, naming each target and its version. |
| `.goreleaser.yml`, `version.go` | A go `binary` pipeline. |
| `.npmignore` | An npm package, written once with the private-path entries and then the project's own. |
| `bin/index.js` | An npm `go-binary` package: the launcher that runs the binary of the platform package npm installed. |
| `.gitignore` lines | Every member: the lines of the shared template it lacks; the `scaffold-gitignore-stale` check reports a member missing one. |
| `experiments/`, `screenshots/` | Every member: the [scratch directories](#scratch-directories). |
| stub `go.mod` files | A Go module: `.strictmetadata/go.mod` at the repository root, and a stub in each other private directory holding a tracked file ([private paths](#private-paths)). |
| `LICENSE` | Written once, while absent, when the member's releasable has a license in effect in the [lifecycle-and-license record](lifecycle-and-license.md) whose text rlsbl carries (MIT), with git's `user.name` as the copyright holder. A missing record, a missing license period, and a proprietary license write none. |
| the test runner script | While `rlsbl:test-sandbox` is on: the sandboxed test runner at the `runner_path` `test-runner.toml` declares. |
| `pyproject.toml` settings | pytest's `norecursedirs` with the scratch directories, an `--ignore=<path>` per nested member in pytest's `addopts`, and hatchling's sdist exclusions; every other byte is kept. |
| `.git/hooks/pre-push`, `.git/hooks/post-rewrite` | Every scaffold: the [git hooks](#git-hooks). |

While `rlsbl:ecosystem-tagging` is on (its default), the npm and PyPI manifests gain the `rlsbl` keyword and the GitHub repository the `rlsbl` topic, so `rlsbl discover` finds the project.

`CHANGELOG.md` and `unreleased.jsonl` are not scaffolded: the first `rlsbl changelog add` creates the changelog directory and file, and `rlsbl changelog generate` writes `CHANGELOG.md`.

In a workspace, the root member is not scaffolded: `rlsbl monorepo sync` generates its workflows. Scaffolding any other member ends by regenerating the workspace's CI router and publish router from the members' workflows, as `rlsbl monorepo sync` does, committed with the same choice as the scaffold; under `--dry-run` that step is named, not previewed. `--skip-shared` leaves the files every member gets (the `.gitignore`, scratch directories, stub `go.mod` files, `LICENSE`, and the test runner) as they are.

## The scaffold state and the three-way merge

Every file scaffold manages is recorded, with its SHA-256, in `.strictmetadata/.scaffold-state/scaffold-state.toml`, beside the rlsbl version that last scaffolded or released the repository. The rendered template of each is kept as a merge base under `.strictmetadata/.scaffold-bases/<path>`. On the next run, three versions of each file exist:

- **ours**, the file on disk, with any edits;
- **base**, what scaffold wrote last time;
- **theirs**, what the templates render now.

| Condition | What scaffold does |
| --- | --- |
| ours equals theirs | Nothing. |
| ours equals base | Takes theirs: the file was not edited and the template changed. |
| base equals theirs | Keeps ours: the template did not change. |
| all three differ | Merges with `git merge-file`. |

A merge that cannot resolve every hunk is written with git's conflict markers (labeled ours, base, and theirs), left uncommitted, and fails the command; `scaffold-conflicts` reports any marker left in a managed file, and every release refuses one. A file with no stored base has its base rebuilt from the file's content at its last `rlsbl scaffold` commit.

A file scaffold managed and no longer renders is removed through saferm, with its base, while it still matches the recorded hash; one edited since is refused before anything is written, naming the saferm command and the way to keep it.

## Scratch directories

Every member gets two scratch directories at its root, `experiments/` (throwaway probes) and `screenshots/` (screenshots taken while checking work), so a tool or an agent has a declared place inside the project for a throwaway file. Each carries a committed `.gitignore`:

```gitignore
*
!.gitignore
```

so the directory exists in a fresh clone while nothing inside it can be committed by accident. A scratch directory already holding tracked files is refused before anything is written, listing them.

The project's own test runner skips them too, by each ecosystem's own setting:

| Ecosystem | What scaffold writes |
| --- | --- |
| Python | Both names in pytest's `norecursedirs` (with pytest's default patterns kept, since the setting replaces them). |
| Go | A `go.mod` in each scratch directory, with `!go.mod` in its `.gitignore`, so `go test ./...` treats it as another module. |
| npm | Nothing: the project's test script names its own runner, whose configuration rlsbl does not own. |

## Private paths

A registry keeps every upload permanently, so an upload may not carry a private path: planning notes (`todo/`), family metadata (`.strictmetadata/`, and the old `.rlsbl/` and `.rlsbl-monorepo/`), tool state (`.selfdoc/`, `.strictcli/`), agent instructions (`CLAUDE.md`, `AGENTS.md`, `.claude/`), scratch output (`experiments/`, `screenshots/`), environment files (`.env*`), and anything named `*.local-only`. The plain names count at the package root, the rest at any depth outside a `testdata` directory. Scaffold writes each ecosystem's exclusion:

| Ecosystem | What scaffold writes |
| --- | --- |
| Python (hatchling) | The entries merged into `exclude` under `[tool.hatch.build.targets.sdist]`; the wheel is built from that sdist. |
| npm | The entries in `.npmignore`, written once. |
| Go | A stub `go.mod` in each private directory holding a tracked file (`module private.invalid/rlsbl-private`, no `go` directive), since Go leaves a directory with its own `go.mod` out of the module zip; `.strictmetadata/go.mod` for the root. |

The `upload-private-paths` check lists an npm package and a Go module zip offline before a release; a Python upload can only be listed by building it, so the pypi CI workflow builds it on every push and runs rlsbl's private-path rule over the sdist and wheel, a Go program embedded in the workflow. Go cannot leave a single file at the module root out of the zip, so a private file there moves into a directory with a stub (`CLAUDE.md` to `.claude/CLAUDE.md`) or stops being committed.

## Git hooks

Scaffold installs two hooks where git runs them:

- **pre-push** runs `rlsbl failing-checks --hook pre-push` for a push to any branch, with git's ref lines in `RLSBL_PUSH_STDIN`; a push of only tags or `refs/backups/*` exits at once ([the pre-push hook](changelog.md#the-pre-push-hook)).
- **post-rewrite** runs `rlsbl changelog remap --stdin`, so changelog entries follow their commits through an amend or a rebase.

An installed hook is replaced only when its content is one rlsbl shipped (compared by hash, trailing whitespace ignored), which upgrades every hook an earlier rlsbl installed. Any other content is refused: a hook that does not run rlsbl's checks lets a push through unchecked.

## Template placeholders

Templates use `{{name}}` variables, `{{action "owner/repo"}}` and `{{actionVersion "x"}}` for pinned action versions, and block placeholders; GitHub's own `${{ ... }}` passes through untouched. The `scaffold-unreplaced-vars` check reports any placeholder left in a member's workflows, goreleaser configuration, or managed files.

## Customizing workflows

Extra jobs go in a workflow file scaffold never touches, so they never meet a template change in a merge: see [customizing CI workflows](ci-customization.md).
