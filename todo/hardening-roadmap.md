# rlsbl hardening roadmap

## Context

A thorough seven-dimension investigation (architecture, release pipeline failure modes, test coverage, changelog/checks, scaffold/monorepo, bug history, consumer fleet) was conducted on v0.69.2/v0.70.0. This todo consolidates the findings into a prioritized work plan. The investigation conversation has full details including file:line references, concrete failure scenarios, and ranked work items per dimension.

## Recurring bug classes (structural root causes)

Three bug classes account for 38 of 72 historical fixes. Each recurs because fixes are localized, not structural:

1. **Monorepo context propagation (16 fixes, v0.61-0.69.1):** pre-push, release, changelog, and config each independently discovered context bugs. Root cause: monorepo support was retrofitted; no single source of truth for "which project am I in." Fix: WorkspaceContext resolved once at CLI entry, threaded everywhere.

2. **Path/CWD handling (11 fixes, v0.39-0.68):** same bug fixed 4+ times in different code paths. Root cause: legacy os.chdir() thinking; path resolution mixes relative and absolute. Fix: ProjectContext class holding (project_root, is_monorepo, monorepo_root), passed explicitly; lint rule against os.getcwd() outside context creation.

3. **Changelog validation exemption rules (11 fixes, v0.42-0.69):** rules added ad-hoc (path patterns, Autogenerated trailer, monorepo detection, changelog-only) without centralization. Fix: ChangelogExemptionRegistry with ordered predicates and per-rule unit tests.

## Pipeline robustness gaps

- **Tag push after commit push (release.py ~1507-1547):** tag push is OUTSIDE the try-catch that handles rollback. If commit pushes but tag push fails, commit is public, no tag, no rollback runs. Fix: wrap both pushes in one try block.
- **GitHub Release creation failure (~1561):** tag is orphaned if gh release create fails. Fix: delete tag on failure or make creation idempotent.
- **Post-release hook side effects (~1662-1674):** hook can create commits that release undo doesn't know about. Fix: document that hooks must be idempotent, or snapshot tree before hook.
- **Monorepo batch partial failure (batch_release.py ~92-123):** packages 1-(N-1) are fully released if package N fails; no coordinated undo. Fix: record released packages, provide batch-level undo or resume.
- **Finalization mid-sequence failure:** if finalize completes but generate_version_file fails, re-run can corrupt (collision guard now exists, but the sequence is still fragile). Fix: detect partial finalization state, require --force to proceed.

## Architecture debt

- **release.py god-module (1705 lines, 21 functions, two >500 lines):** split into validate/execute/rollback modules.
- **34 sys.exit calls in release.py:** replace with exception hierarchy (ReleaseAbortError, ReleaseValidationError); catch at top-level main().
- **Mutable module-level state in __init__.py:** _variadic_args and _resolved_project are module globals mutated at runtime.
- **ReleaseConfig is a raw tomlkit dict:** should be a dataclass with __post_init__ validation.
- **No mypy/pyright in CI:** type hints exist but are never validated.

## Changelog subsystem bugs

- **Cross-project batch limits (validate.py ~467-506):** check_batch_size_entries reads ALL JSONL files regardless of project scope. In monorepos with shared commits, this causes false positives. Fix: filter entries by project.
- **Exclusion hash matching (validate.py ~496-505):** abbreviated hash in entry vs full hash in exclusion; string equality fails. Fix: resolve both to full SHA before comparison.
- **Partial orphan messaging (validate.py ~389-400):** entries with 1 resolvable hash (out of range) + N unresolvable hashes produce confusing error messages. Fix: separate warning for this pattern.

## Target detection

- **Collision resolution (13 fixes, v0.35-0.65):** PlainTarget vs DocsTarget, Go library vs cmd, npm moniker. Fix: explicit priority matrix with collision tests; detection stops at first match in priority order.

## Test coverage gaps

- **Push timeout scenario:** zero tests for git push hanging/timing out.
- **GitHub API transient errors (429, 503):** mocks always succeed; no retry/backoff tests.
- **Repository edge states:** no tests for detached HEAD, shallow clone, missing origin, tag-already-exists.
- **Monorepo mid-batch crash + recovery:** no test for manual resume after partial batch.
- **Self-release E2E:** no test simulating rlsbl releasing itself.
- **No coverage reporting in CI.**

## Consumer fleet

- **Incantino (0.54.2):** fifteen minor versions behind; 7 sub-packages need coordinated re-scaffold.
- **0.67.1 cohort (16 projects):** two minor versions behind; re-scaffold will attempt large merges.
- **The new scaffold-conflicts check guards re-scaffolding** — conflict markers will be caught before release.
