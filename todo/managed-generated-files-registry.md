# Managed generated-files registry: commit enforcement + unified staleness

## Context

Fleet programs generate files that are committed to repos by
convention (never gitignored): selfdoc's template-generated root files
(`README.md`, `CLAUDE.md`) and per-version docs, rlsbl's
`CHANGELOG.md` and per-version `.md` files, `.validated` caches, code
maps, typed codegen outputs from other tools. selfdoc already marks
its outputs (an "auto-generated" header comment + chmod 444), which is
the right presentation — but enforcement and staleness detection are
per-tool and ad hoc.

## Problem

1. **Nothing prevents out-of-band edits or commits of generated
   files.** Read-only bits are advisory (git commits don't care), and
   a session that hand-edits a generated file corrupts state the owner
   tool will silently clobber on its next run — or worse, won't.
2. **Staleness detection is scattered.** Each tool has its own way (or
   none) to answer "are my generated files up to date with their
   sources?" There is no way to sweep a whole project.
3. **No single enumeration exists**: which files in this repo are
   generated, who owns each, how to regenerate, how to check.

## Proposed design

Owner programs **register** their managed files, each registration
carrying: the owner's name, the glob patterns it manages, and two
mandatory commands —

1. **regenerate** — rebuild the files from their sources
2. **check-staleness** — exit 0 fresh / non-zero stale, with a
   machine-readable list of stale paths

On top of the registry:

- **Commit enforcement**: safegit refuses to commit changes to managed
  files unless the commit goes through the sanctioned route — `rlsbl
  commit` executed by/for the owner program (identity carried by a
  handshake, e.g. env var + `Autogenerated: true` trailer). A refused
  commit names the owner and its regenerate command (corrective
  error).
- **Presentation contract**: registered files carry a first-line
  header ("generated by <owner> — do not edit") and chmod 444
  (selfdoc precedent); a check verifies both.
- **Unified surface**: `rlsbl generated status` iterates every owner's
  check-staleness across the project; `rlsbl generated regen
  [--owner X | --all]` resolves it. A check tag (e.g. `generated`)
  lets preflight/prepush block on stale generated files.

## Solutions / variants

**Registration shape**

- **A. Config-declared** (`.rlsbl/config.json` key, e.g.
  `managed_files`: owner + patterns + the two commands). Pros: simple,
  visible, greppable, no protocol work in owner tools. Cons: per-repo
  duplication; config drifts from what the owner tool actually
  generates.
- **B. Self-registration protocol**: owner tools expose a
  `--managed-files-manifest` command that rlsbl invokes to learn
  patterns + commands. Pros: single source (the owner tool), no
  per-repo drift. Cons: every owner must implement the protocol;
  discovery of which owners exist still needs config.
- **C. Hybrid** — config lists the owners, each owner supplies
  patterns/commands via protocol. Pros of both; likely the right
  shape.

**Enforcement point**

- **safegit commit-time guard**: earliest catch, concurrency-safe,
  works for every session. Cons: safegit must read the registry.
- **rlsbl prepush check**: centralized, no safegit change. Cons:
  catches late; raw-git commits of managed files sit in history until
  push.
- **Both** (defense in depth): commit-time for the common path,
  prepush as the backstop that also catches raw-git commits.

**Sanctioned-route handshake** (needs its own design pass): how the
owner program's identity is proven to safegit — env handshake set by
`rlsbl commit`, a trailer convention, or a registry-issued token file.
The handshake must not be spoofable by simply exporting a variable, or
it's a convention wearing an enforcement costume.

## Affected

- **rlsbl**: config schema; new `generated` command family; a check
  (tag `generated` or similar) wired into preflight/prepush; the
  commit-route handshake in `rlsbl commit`.
- **safegit**: managed-file guard in the commit path; sanctioned-route
  recognition.
- **selfdoc**: register as the first owner (root files, per-version
  docs); it already has the header + chmod discipline.
- **Scaffold templates**: default registration entries for the tools
  the scaffold wires.

## Effort

Medium-large, cross-tool (rlsbl + safegit + at least one owner
adoption). The registry and `generated` command family are
straightforward; the enforcement handshake is the part needing a
design round.
