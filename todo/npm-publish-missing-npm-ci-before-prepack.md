# npm publish workflow template lacks `npm ci` before publish

## Problem

The generated npm publish workflow runs `npm publish` without first installing
the package's devDependencies. `npm publish` triggers the package's `prepack`
lifecycle script, which for TypeScript packages runs a build (`npm run build` ->
`tsc`). `tsc` needs devDependencies (`@types/node`, `typescript`) that are NOT
present on a fresh CI runner, so the build fails with:

```
error TS2688: Cannot find type definition file for 'node'.
```

The publish job checks out the source, sets up node, and jumps straight to the
`npm publish` step — there is no `npm install`/`npm ci` between setup-node and
publish. So the prepack build always runs against an empty `node_modules`.

## Affected template(s)

- `rlsbl/templates/npm/publish.yml.tpl` — the `npm publish` step (around line
  66) has no preceding install step. The monorepo publish router generated by
  `rlsbl monorepo sync` inlines this per-project publish job, so the same gap
  propagates into inlined router jobs.
- Check the sibling templates too: `publish-yarn.yml.tpl`, `publish-pnpm.yml.tpl`,
  `publish-launcher.yml.tpl` — any that call the packager's publish without a
  prior dependency install have the same class of bug.

## Fix

Insert an install step after `setup-node` and before the publish step, e.g.:

```yaml
      - name: Install dependencies (incl. devDependencies for prepack build)
        run: npm ci
```

Use `npm ci` (or `npm ci --include=dev` to be explicit that dev deps are
required for the prepack build). Yarn/pnpm variants need their equivalent
(`yarn install --frozen-lockfile`, `pnpm install --frozen-lockfile`).

## Empirical evidence

A SECOND ecosystem project (an npm-target package that ships a first-run
launcher shim, so its build compiles TypeScript in `prepack`) has now
independently hit this exact TS2688 failure during a real publish run. Both
affected consumers fixed it the same way — hand-adding `npm ci` before publish
to their generated workflow. Two independent reproductions of the same template
gap: the template is the root cause and should be fixed once, upstream.

## Red-green expectation

1. RED: add a test that renders the npm publish template (and the monorepo
   publish router) and asserts an install step (`npm ci`) exists AND appears
   before the `npm publish` step. Verify it fails against the current template.
2. GREEN: add the install step to the template; verify the test passes.

Because the real-world symptom is an interaction (publish -> prepack -> tsc ->
missing dev deps), a render-level assertion that "install precedes publish" is
the right granularity; a full CI integration test that actually runs a
prepack build with no dev deps would also reproduce it but is heavier.

## Effort

Small — a one-line template step plus a render assertion, times the packager
variants that share the gap.
