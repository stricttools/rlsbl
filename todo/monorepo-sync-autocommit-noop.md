# monorepo sync autocommit fails when no files changed

## Problem

`rlsbl monorepo sync` calls `safegit commit` with a list of workflow files it processed, but some of those files may not have actually changed (already committed from a previous sync). When no files are dirty, `safegit commit` fails with "nothing to commit (tree unchanged)".

The warning is:
```
Warning: commit failed: Command '['safegit', 'commit', '--trailer', 'Autogenerated: true', '-m', 'monorepo: sync CI workflows', '--', ...]' returned non-zero exit status 1.
```

## Root Cause

`monorepo sync` always attempts to commit the full list of synced files, regardless of whether git has any actual changes staged. It should check `git diff --cached --quiet` or filter the file list to only files that are actually dirty before attempting the commit.

## Proposed Fix

Before calling `safegit commit`, run `git status --porcelain -- <files>` and only commit if there are changes. If all files are unchanged, skip the commit silently or print "No workflow changes to commit."

## Affected Code

`rlsbl/commands/monorepo_cmd.py` — the sync function's commit block.

## Effort

Small.
