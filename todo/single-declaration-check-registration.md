# Collapse the four-place check registration into a single declaration

## Background

Registering a check currently requires four hand-maintained places kept in
agreement: the implementation (an error_check/warn_check decorator in a
checks module), the metadata entry in rlsbl/data/checks.toml (tags,
severity, fast, pure, needs_network, depends_on, scope), the
check-to-target applicability entry in the CHECK_TARGETS dict in
rlsbl/checks/__init__.py, and a table row in docs/checks.md. Freshness
tests (test_docs_check_tables, test_feature_matrix, test_check_purity)
fail when the places disagree — the assert-the-copies-agree fallback shape
rather than a single authority. Dozens of checks exist and more keep being
added; every registration pays the four-place tax, and drift between the
places is prevented only by tests, not by construction.

The same repository's target support work replaces exactly this shape for
targets (single authority in code, generated committed artifact, derived
docs tables), so the convention is also internally inconsistent with the
project's own direction.

## What to consider doing

- Declare everything once at the check decorator: metadata (tags,
  severity, fast, pure, needs_network, depends_on, scope) and target
  applicability become decorator arguments or adjacent declarations in
  the implementation module — the single authority.
- Generate rlsbl/data/checks.toml from the declarations (committed via
  the autogenerated-commit convention) or retire the file in favor of
  runtime registration, whichever keeps external tooling that reads the
  file working.
- Generate the docs/checks.md tables via a docs directive (the directive
  family already exists for target tables, feature matrix, pipeline
  tables, and counts — a check-table directive is the one nobody wrote).
- Collapse CHECK_TARGETS into the same declarations; the feature-matrix
  generation reads the registry instead of a parallel dict.
- The freshness tests reduce to one: generated artifacts match the
  declarations.

## Why

One declaration cannot drift from itself; four places can and only tests
stand in the way. Every future check registration becomes a single edit,
and the docs stop being hand-maintained restatements of code.
