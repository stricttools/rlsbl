# The go target's test-suite check hardcodes `go test ./...`

## Context

The `test-suite` check (tagged prepush, quality and preflight, error
severity) runs `go test ./...` for every Go target with no configuration
hook. A Go module written in a dialect whose entry point is generated by a
front-end tool cannot pass a plain `go test`: its tests dispatch through a
registered app that only the tool's generated entry provides, so every test
panics with `program was not built by <tool>; run <tool> test`. Such a module
declares its own pre-release hooks (`<tool> test . -- -race -count=1`), but
the built-in check still runs the plain command and blocks the push and the
preflight.

## Problem

A go target's test command is not configurable, and a module whose tests run
through another tool has no way to say so.

## Proposal

A `test_command` key on the go target (and on every target whose test-suite
check runs a fixed command), an argv the check runs from the module
directory in place of the default; the default stays `go test ./...`. The
check's message names the command it ran. A fixture with `test_command`
pointing at a script asserts the substitution.

## Alternatives

- Declare the check disabled for such a module. Loses the check entirely
  where a substitute command would keep it.

## Affected files

- `rlsbl/targets/go.py` (the test-suite check), the config schema, the
  reference documentation of the key.

## Effort

Small.
