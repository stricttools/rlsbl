# Trailer-based changelog coverage exemption

## Summary

Replace path-pattern matching (`_is_changelog_only_commit`) and commit-message regex (`_is_release_commit` / `_RELEASE_MSG_RE`) with a git trailer-based exemption system. Any commit with `Autogenerated: true` in its trailers is automatically exempt from changelog coverage.

## Motivation

The current exemption logic accumulates guardrails:
- `_CHANGELOG_PATTERNS` in `_is_changelog_only_commit` checks file path suffixes
- `_RELEASE_MSG_RE` matches commit message format `^([\w-]+: release )?v\d+\.\d+\.\d+$`
- Every new generated-file type (selfdoc cache, `.validated`, etc.) needs a new pattern

A trailer is self-describing structured metadata. Tools mark their own commits; no central pattern list needed.

## Design

### Trailer format

`Autogenerated: true` — capitalized per git trailer convention. Generic, tool-agnostic.

### `rlsbl commit` command

New command for tools to make changelog-exempt commits:

```bash
rlsbl commit -m "message" -- file1 file2
```

Behavior:
- Tries `safegit commit --trailer "Autogenerated: true" -m "..." -- files`
- If safegit not found, warns once per session, falls back to `git commit --trailer "Autogenerated: true" -m "..." -- files`
- Supports all flags that safegit/git commit supports (pass-through)

### Coverage check

Replace `_is_changelog_only_commit(sha)` and `_is_release_commit(sha)` with a single `_is_autogenerated(sha)` that checks:

```
git log -1 --format=%(trailers:key=Autogenerated,valueonly) <sha>
```

If the output is `true`, the commit is exempt.

### Remove old logic

Remove immediately (no backward-compat shim):
- `_CHANGELOG_PATTERNS` tuple and suffix-matching loop in `_is_changelog_only_commit`
- `_RELEASE_MSG_RE` regex and `_is_release_commit` function
- All pattern-based exemption logic

This is safe because:
- Coverage only checks commits in the unreleased range (last tag..HEAD)
- After any release, the range resets
- Old commits before the trailer was introduced are behind the last tag and never re-checked

### Rlsbl's own generated commits

Replace raw `safegit commit` / `git commit` in the release flow with `rlsbl commit`:
- Changelog finalization commit (`chore: finalize changelog for ...`)
- Any other internal auto-commits

The release version-bump commit itself stays as-is (it's user-facing, not autogenerated).

### Future: configurable trailer list

Deferred. Currently hardcoded to `Autogenerated`. Later, add a config key (e.g., `skip_trailers: ["Autogenerated", "Autogenerated-By-Selfdoc"]`) so projects can recognize additional trailer keys. Also a future consideration: unify monorepo (toml) and standalone (json) config formats.

## Affected files

- `rlsbl/changelog/validate.py` — replace `_is_changelog_only_commit`, `_is_release_commit`
- `rlsbl/commands/pre_push_check.py` — imports `_is_release_commit`, needs updating
- `rlsbl/commands/status.py` — imports `_is_changelog_only_commit`, needs updating
- `rlsbl/commands/release.py` — finalization commits use `rlsbl commit`
- `rlsbl/__init__.py` — register new `commit` command
- New file for the commit command implementation

## Phases

1. Fix `.validated` abort (add to `files_to_commit` — immediate unblock)
2. `rlsbl commit` command (tries safegit, falls back to git, adds trailer)
3. Coverage check reads trailer (replace pattern matching, remove old logic)
4. Rlsbl's generated commits use `rlsbl commit`

## Effort

Medium — each phase is small but they chain. Phase 1 is a one-liner. Phase 2 is a new command (~50 lines). Phase 3 is a refactor of validate.py + callers. Phase 4 is updating release.py's commit calls.
