# `rlsbl commit --dry-run` creates a real commit

## Context

During a fix-forward session, `rlsbl commit --dry-run -- <generated files>`
was run to preview the Autogenerated-trailer commit — and it created the real
commit instead of previewing it.

## Problem

`--dry-run` is a global flag documented as available on all commands. The
`commit` command ignores it entirely: the commit executes with the trailer as
if the flag were absent. A preview-intent invocation mutating history violates
the flag's contract and the no-silent-degradation principle (the tool did
something materially different from what was asked, silently).

## Expected

`rlsbl commit --dry-run` prints what would be committed (files, message,
trailer) and exits without touching the repository. A red-green test should
pin this for `commit` and, ideally, a sweep should verify every command that
accepts the global `--dry-run` actually honors it (a registration-time or
test-time contract, not per-command goodwill).

## Effort

S for the commit fix; M with the all-commands dry-run contract sweep.
